From Model to Experiment — Reading the Equations to Design the Test

Establishes the connection between a physical model and the experimental design required to test it — and the connection between that design and the uncertainty budget. The lecture opens with a direct question: given a model equation, what does it tell you about what to measure, how precisely, and under what conditions? The answer lives in the partial derivatives. Each term in an error propagation expression is a sensitivity — it quantifies how much the derived output changes per unit of error in that input. A large sensitivity on a poorly characterized input is the dominant error source; a small sensitivity on a noisy input may be negligible. This is exactly the P=IV lesson from Lab 1, generalized: P=I²R is more sensitive to current than to resistance, so a current-measurement error has greater consequence than the same proportional error in resistance. That logic applies to any model. **Worked example (model-driven design):** Walk through a simple dynamics model from the Tier 1 experiment pool — e.g., an angular velocity expression for an unbalanced wheel or a damped oscillation equation — and use the partial derivatives to identify: (1) which measured quantity dominates the uncertainty budget, (2) what that implies about sensor selection (which input needs the tightest spec?), (3) what range of the independent variable would make the model comparison most informative (where is the model most sensitive to the parameter being estimated?), and (4) what anomalous behavior would look like if a model assumption breaks down. The key message: the model is not just a thing you compare data to — it is a design document for the experiment itself. Students who read their model before they set up the hardware make better instrumentation choices and write more defensible reports.

Learning Objectives

  • Read a physical model's equations to identify what must be measured, how precisely, and under what conditions — connecting model structure to experimental design requirements — CLO 1, CLO 3
  • Rank the contributions of multiple error sources in a measurement chain and articulate where improving one input would most reduce total uncertainty in the derived output — CLO 2
  • Execute a complete Phase I experimental pipeline — hypothesis, sensor selection, installation, MATLAB-based data collection, uncertainty propagation, and quantitative model comparison — as a single traceable workflow — CLO 1, CLO 2, CLO 3
  • Write explicit sensor selection rationale connected to accuracy requirements and intended use — CLO 1
