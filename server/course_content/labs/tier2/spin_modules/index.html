Tier 2 Candidate

Spin Modules

Evaluate gyro calibration, reaction-wheel and spacecraft-body inertia estimates, coast-down resistance, and rotational-response uncertainty across useful angular-rate and applied-torque conditions.

30,000 Ft View

In this experiment you will use the CU Boulder spin module to determine which reaction-wheel torque conditions support a reliable prediction of base rotational velocity. The core deliverables are an uncertainty envelope versus applied reaction-wheel torque, a rotational-model prediction, comparison with the encoder base-rate reference, and residual interpretation.

Tier 2 Elevator Pitch

Students act as consultants evaluating whether the spin module can predict base rotational behavior reliably across a range of applied reaction-wheel torques. They distinguish commanded torque from current-inferred torque, map uncertainty against torque, compare predicted and encoder base rates, and recommend where to test and what measurement or setup change would improve the experiment. Gyro calibration is supporting work only when needed.

Overview

Overview - Spin Modules

In this lab, you will work with a single-axis spacecraft mockup called the CU Boulder Spin Module. The experiment focuses on selecting reaction-wheel torque conditions that produce a reliable prediction of base rotational velocity.

The student-facing core of this lab is:

  • map commanded torque and current-inferred reaction-wheel torque;
  • analyze base-rate uncertainty versus applied reaction-wheel torque;
  • select appropriate, marginal, and inappropriate torque conditions;
  • use supplied or fitted inertia and resistance parameters in a rotational model;
  • compare predicted base rate with the encoder base-rate reference;
  • produce residuals versus applied reaction-wheel torque and interpret their trends.

By the end of the lab, you should be able to:

  • identify the measurement chain connecting the gyro, encoder, Hall sensors, current sensors, myRIO, Arduino DUE, Xbee link, and LabVIEW VI
  • explain how current, motor torque constant, encoder rate, inertia, resistance, timing, and

model form affect confidence in the prediction

Placeholder: the instructor must identify which inertia and resistance parameters are supplied, fitted, or provisional, and must define the approved torque/rate limits.

Tier 2 Positioning

For Tier 2, this is an engineering investigation of the spin-module measurement envelope. Students first analyze uncertainty in base rotational velocity versus applied reaction-wheel torque. They then use the selected torque conditions to predict base rate, compare it with the encoder reference, and interpret residuals. The deliverable is a defensible test recommendation and a quantitatively justified setup alteration, not a complete controls design.

Theoretical Framework - Spin Modules Tier 2 Experiment

This framework supports the revised application: uncertainty in base rotational velocity versus applied reaction-wheel torque, rotational prediction, encoder comparison, residual analysis, and uncertainty propagation. Parameter identification is supporting work when needed to establish the model.

1. Applied torque and measurement chain

\[ \tau_{\mathrm{cmd}}=\text{commanded reaction-wheel torque}, \qquad \tau_{\mathrm{inf}}=k_{t,\mathrm{RW}}I_{\mathrm{RW,motor}}. \]

Keep commanded and current-inferred torque separate. State which one enters the model and propagate the uncertainty in the other quantity or use their difference diagnostically.

2. Base-rate prediction

Use the instructor-supplied sign convention and model:

\[ I_{\mathrm{base}}\dot{\omega}_{\mathrm{base}} +c_{\mathrm{base}}\omega_{\mathrm{base}} +\tau_{0,\mathrm{base}}\operatorname{sgn}(\omega_{\mathrm{base}}) =s_\tau\tau_{\mathrm{applied}}. \]

Here \(s_\tau\) is the verified sign relating reaction-wheel torque to base torque. State whether \(I_{\mathrm{base}}\), \(c_{\mathrm{base}}\), and \(\tau_{0,\mathrm{base}}\) are supplied, fitted, or provisional. Integrate the model when a rate history is required.

3. Supporting parameter identification

When an inertia or resistance parameter is needed and is not supplied, use a documented fitting window:

\[ I=\frac{\tau}{\dot{\omega}}, \qquad \tau=k_t I_{\mathrm{motor}}, \]

and, for resistance,

\[ I\dot{\omega}+c\omega+\tau_0\operatorname{sgn}(\omega)=\tau_{\mathrm{applied}}. \]

Do not make a separate gyro, base-motor, or coast-down study central unless it is needed to establish a parameter used by the base-rate prediction. Label every parameter as measured, fitted, supplied, or provisional.

4. Encoder comparison and residuals

Use the base encoder as the truth/reference sensor:

\[ r_\omega(\tau_{\mathrm{applied}}) = \omega_{\mathrm{base,predicted}}(\tau_{\mathrm{applied}}) - \omega_{\mathrm{base,encoder}}(\tau_{\mathrm{applied}}). \]

Plot residuals versus applied torque. Interpret trends using sensor uncertainty, torque uncertainty, parameter uncertainty, friction/resistance, timing, and model-form error.

5. Tier 2 uncertainty envelope

Use applied reaction-wheel torque as the primary condition variable. For base rotational velocity \(y=\omega_{\mathrm{base}}\), report

\[ \mathrm{SSU}_{y,\mathrm{sys}}(q)=b_{y,\mathrm{sys}}(q), \qquad \mathrm{NSU}_{y,\mathrm{sys}}(q)=\frac{b_{y,\mathrm{sys}}(q)}{|y(q)|}, \]

where \(q\) is applied reaction-wheel torque. Use Taylor-series sensitivity coefficients and Monte Carlo propagation at representative conditions. Near a nominal zero, use absolute uncertainty and do not interpret the relative curve through the zero.

6. Supporting gyro calibration

If assigned or needed to establish base-rate uncertainty, use

\[ \omega_{\mathrm{gyro}}=K\omega_{\mathrm{true}}+b, \qquad \omega_{\mathrm{calibrated}}=\frac{\omega_{\mathrm{gyro}}-b}{K}. \]

The encoder remains the truth/reference sensor for the primary base-rate comparison.

Model Equations Reference - Spin Modules Tier 2 Experiment

This reference supports the revised Tier 2 application: uncertainty in base rotational velocity versus applied reaction-wheel torque, rotational prediction, encoder comparison, residual analysis, and uncertainty propagation. Parameter estimation is supporting work only when needed to establish the model.

1. Applied torque definition

Keep commanded and inferred torque separate:

\[ \tau_{\mathrm{cmd}}=\text{commanded reaction-wheel torque}, \qquad \tau_{\mathrm{inf}}=k_{t,\mathrm{RW}}I_{\mathrm{RW,motor}}. \]

Use the torque quantity specified by the instructor or justified by the data as the model input. Propagate uncertainty in the other quantity or use the difference between them as a diagnostic. The motor torque constant \(k_{t,\mathrm{RW}}\) must be labeled as supplied, measured, fitted, or provisional.

2. Base-rate rotational model

Use the supplied sign convention and parameter definitions. A generic working form is

\[ I_{\mathrm{base}}\dot{\omega}_{\mathrm{base}} +c_{\mathrm{base}}\omega_{\mathrm{base}} +\tau_{0,\mathrm{base}}\operatorname{sgn}(\omega_{\mathrm{base}}) =s_\tau\,\tau_{\mathrm{applied}}, \]

where \(s_\tau\) is the instructor-verified sign relating reaction-wheel torque to base torque. If the supplied model includes additional terms, use that model and state the difference. The required output is the predicted base rotational-rate history or condition response.

For a specified torque and rate,

\[ \dot{\omega}_{\mathrm{base}} = \frac{s_\tau\tau_{\mathrm{applied}} -c_{\mathrm{base}}\omega_{\mathrm{base}} -\tau_{0,\mathrm{base}}\operatorname{sgn}(\omega_{\mathrm{base}})} {I_{\mathrm{base}}}. \]

State whether \(I_{\mathrm{base}}\), \(c_{\mathrm{base}}\), and \(\tau_{0,\mathrm{base}}\) are supplied, fitted, or provisional.

3. Supporting gyro calibration

If assigned or needed to establish base-rate uncertainty, model the raw gyro output as

\[ \omega_{\mathrm{gyro}}=K\omega_{\mathrm{true}}+b, \qquad \omega_{\mathrm{calibrated}}=\frac{\omega_{\mathrm{gyro}}-b}{K}. \]

Fit \(K\) and \(b\) from calibration data only when the instructor assigns this supporting analysis. The encoder remains the truth/reference sensor for the primary base-rate comparison.

4. Supporting inertia and resistance parameters

For a supporting reaction-wheel or base-motor trial, use

\[ I=\frac{\tau}{\dot{\omega}}, \qquad \tau=k_t I_{\mathrm{motor}}, \]

only when that parameter is needed by the base-rate model. Use a documented fitting window and distinguish measured, fitted, supplied, and provisional values.

For a coast-down or resistance fit, use

\[ I\dot{\omega}+c\omega+\tau_0\operatorname{sgn}(\omega)=\tau_{\mathrm{applied}}. \]

During coast-down, \(\tau_{\mathrm{applied}}=0\). Do not make coast-down a central deliverable unless it is needed to support the prediction.

5. Encoder comparison and residuals

Treat the encoder base-rate channel as the truth/reference sensor for the primary comparison:

\[ r_\omega(\tau_{\mathrm{applied}}) = \omega_{\mathrm{base,predicted}}(\tau_{\mathrm{applied}}) - \omega_{\mathrm{base,encoder}}(\tau_{\mathrm{applied}}). \]

Plot residuals versus applied torque and, where useful, versus time or measured rate. Interpret trends using sensor uncertainty, torque uncertainty, parameter uncertainty, friction/resistance, timing, and model-form error.

6. Condition-dependent uncertainty

The primary sweep variable is applied reaction-wheel torque. Propagate uncertainty from current, \(k_{t,\mathrm{RW}}\), command calibration, inertia, resistance, timing, and encoder/base-rate measurement. Calculate absolute and relative uncertainty in base rotational velocity:

\[ \mathrm{SSU}_{\omega,\mathrm{base},\mathrm{sys}}(q) =b_{\omega,\mathrm{base},\mathrm{sys}}(q), \]

\[ \mathrm{NSU}_{\omega,\mathrm{base},\mathrm{sys}}(q) = \frac{b_{\omega,\mathrm{base},\mathrm{sys}}(q)} {\lvert\omega_{\mathrm{base}}(q)\rvert}, \]

where \(q\) is the applied reaction-wheel torque. Near a nominal zero, use absolute uncertainty and do not interpret the relative curve through the zero.

Procedure

Procedure - Spin Modules Tier 2 Experiment

> Lab: Reaction-wheel torque, base rotational-rate prediction, and uncertainty > > Hardware: CU Boulder Spin Module, reaction-wheel motor, base encoder, current channel, > rate channels, DAQ, and LabVIEW interface > > Software: LabVIEW VI and MATLAB analysis tools

Purpose

Act as an engineering consultant evaluating whether the spin module can predict base rotational velocity reliably over a range of applied reaction-wheel torques. The uncertainty analysis comes first: use it to select torque conditions, then use a rotational model to predict base rate, compare the prediction with the encoder base-rate reference, and interpret residuals.

Gyro calibration is supporting work only when it is needed to establish base-rate uncertainty or when the instructor assigns it. Solar-panel comparison, saturation-time analysis, controller design, and unrelated hardware redesign are outside the required scope.

Safety and setup

Follow the instructor's power-up and wind-down procedure exactly. Clamp the spin module before any motor command. Verify power-supply settings, battery condition, communication status, and the approved torque, current, speed, and mechanical limits before testing. Do not change LabVIEW operating modes while the VI is running. Stop the VI before changing tabs or wiring.

Record the software version, hardware/setup identifier, battery state if available, channel names, units, sign conventions, and any dropout or status flags. Preserve raw files without overwriting them.

Applied-torque definition

Record both the commanded and current-inferred quantities:

\[ \tau_{\mathrm{cmd}}=\text{commanded reaction-wheel torque}, \qquad \tau_{\mathrm{inf}}=k_{t,\mathrm{RW}}I_{\mathrm{RW,motor}}. \]

Use the instructor-approved torque constant and current calibration. Do not assume that \(\tau_{\mathrm{cmd}}=\tau_{\mathrm{inf}}\). State which quantity enters the rotational model and propagate uncertainty in the other quantity or use their difference diagnostically. Label \(k_{t,\mathrm{RW}}\) as supplied, measured, fitted, or provisional.

Day 1 - Measurement model and uncertainty-based test selection

  1. Map the reaction-wheel current, motor torque constant, reaction-wheel rate, base encoder

rate, time, DAQ, and data-reduction chain.

  1. Confirm the base encoder is the truth/reference sensor for the primary predicted-versus-

measured base-rate comparison.

  1. Identify the inertia and resistance parameters required by the supplied rotational model.

Mark each parameter as supplied, fitted, or provisional.

  1. Use the available sensor specifications and parameter uncertainties to calculate an initial

uncertainty envelope for base rotational velocity versus applied reaction-wheel torque.

  1. Define the decision rule for appropriate, marginal, and inappropriate torque conditions.

Do not invent an operating limit or numerical acceptance threshold.

  1. Commit to torque conditions that test the predicted low-uncertainty region, high-uncertainty

region, and any proposed decision boundary.

Day 2 - Reaction-wheel torque and base-rate data

  1. Verify the reaction-wheel and base-rate channels, units, signs, timestamps, and status

flags.

  1. Select the assigned torque command and record both \(\tau_{\mathrm{cmd}}\) and the

current-inferred \(\tau_{\mathrm{inf}}\) where available.

  1. Collect or inspect multiple reaction-wheel torque trials over the committed range.
  2. Preserve the base encoder rate and reaction-wheel rate channels with the current and time

channels. Record any command transitions, dropouts, saturation, or nonsteady intervals.

  1. Include at least one condition predicted to be marginal or uncertainty-dominated when safe

and permitted, so the recommendation is tested rather than assumed.

Day 3 - Model, uncertainty, and residual analysis

  1. Estimate or import the inertia and resistance parameters required by the model. Use a

documented fitting window if parameters are estimated from reaction-wheel, base-motor, or coast-down data.

  1. Use the supplied sign convention and rotational model to predict base rate:

\[ I_{\mathrm{base}}\dot{\omega}_{\mathrm{base}} +c_{\mathrm{base}}\omega_{\mathrm{base}} +\tau_{0,\mathrm{base}}\operatorname{sgn}(\omega_{\mathrm{base}}) =s_\tau\tau_{\mathrm{applied}}. \]

  1. Run Taylor/sensitivity and Monte Carlo propagation for base rotational velocity versus

applied reaction-wheel torque.

  1. Compare the predicted base rate with the encoder base-rate measurement.
  2. Calculate residuals:

\[ r_\omega =\omega_{\mathrm{base,predicted}}-\omega_{\mathrm{base,encoder}}. \]

  1. Plot the residuals versus applied torque and, where useful, time or measured rate.
  2. Separate sensor uncertainty from torque uncertainty, parameter uncertainty,

friction/resistance, timing, and model-form error.

Day 4 - Targeted validation and recommendation

  1. Select targeted repeat conditions near the predicted low-uncertainty region, a

high-uncertainty region, and any proposed boundary.

  1. Compare the repeated measurements with the predicted uncertainty envelope and residual

trends.

  1. Decide which torque conditions are appropriate, marginal, or inappropriate according to

the stated decision rule.

  1. Quantify one feasible improvement, such as current/torque resolution, torque calibration,

encoder measurement, timing, resistance characterization, sampling, or parameter estimation, and show how it changes the useful envelope.

  1. Document limitations caused by provisional parameters, missing sensor specifications,

timing gaps, or unverified operating limits.

Required data products

  • Measurement-chain diagram with commanded torque, current-inferred torque, rate channels,

encoder reference, timing, and data reduction.

  • Table of supplied, fitted, and provisional parameters with units and uncertainties.
  • Base rotational-velocity uncertainty envelope versus applied reaction-wheel torque, including

absolute and relative forms where the relative form is meaningful.

  • Rotational-model prediction of base rate using the selected torque definition.
  • Encoder comparison and residuals versus applied reaction-wheel torque.
  • Taylor-series and Monte Carlo comparison at representative conditions.
  • Interpretation of residual trends and a decision-rule-based recommendation.
  • Quantitatively justified instrumentation or setup improvement.

Data-quality checks

  • Confirm that commanded and measured/inferred torque are not silently conflated.
  • Use recorded time rather than assuming perfectly uniform sampling.
  • Do not differentiate noisy rates without documenting the fit, smoothing, or differentiation

method.

  • Check for current clipping, motor saturation, encoder quantization, wireless dropouts,

battery degradation, sign errors, and command-transition artifacts.

  • Treat the encoder as the reference sensor for the primary base-rate comparison.
  • State clearly which parameters are supplied, fitted, or provisional.

FAQs

FAQs - Spin Modules

What are the core deliverables for this lab?

Analyze uncertainty in base rotational velocity versus applied reaction-wheel torque. Use the uncertainty result to choose torque conditions, predict base rate, compare it with the encoder base-rate reference, and interpret residuals versus applied torque.

Are angular momentum capacity and saturation time required?

They are optional enrichment calculations unless your instructor explicitly assigns them. The core Tier 2 result is the uncertainty envelope and test recommendation.

What parameters may be supplied?

Inertia, resistance, motor-constant, encoder, and current-sensor values may be supplied, fitted, or provisional. Label the source and status of each parameter; do not invent a missing value.

Which sensor is the truth reference for the base-rate comparison?

Use the base encoder as the truth/reference sensor for comparing predicted and measured base rotational rate.

What motor constants do I need?

The reaction-wheel motor torque constant is needed when torque is inferred from current. State the commanded torque and current-inferred torque separately:

\[ \tau_{\mathrm{inf}}=k_{t,\mathrm{RW}}I_{\mathrm{RW,motor}}. \]

What changes for Tier 2?

The core sequence is uncertainty in base rate versus reaction-wheel torque, torque-condition selection, rotational-model prediction, encoder comparison, residual interpretation, and one quantified setup improvement.

Should the uncertainty plot use angular rate or torque?

Use applied reaction-wheel torque as the primary design variable. If you use commanded torque and current-inferred torque separately, explain which one enters the model and propagate the uncertainty in the other. Angular rate may be used as a secondary diagnostic.

Is the full resistance model required?

The Tier 2 prediction should use the lumped model

\[ I\dot{\omega}+c\omega+\tau_0\operatorname{sgn}(\omega)=\tau_{\mathrm{applied}}. \]

Use supplied or fitted \(c\), \(\tau_0\), and inertia parameters as required by the branch model. Identify whether each is measured, fitted, supplied, or provisional, and include its uncertainty or limitation.

Is gyro calibration required?

Not as the primary application. Use it as supporting work if it is needed to establish base-rate uncertainty or if the instructor assigns it.

What is outside the four-day scope?

Complete controller design, solar-panel comparison, saturation-time analysis, and detailed hardware redesign are enrichment topics unless explicitly assigned.
