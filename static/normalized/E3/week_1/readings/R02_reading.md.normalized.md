# Experimental-Design Proposal: Concept Check
## Use this guide to develop the existing proposal

This guide supports the existing Tier 3 proposal checkpoint. It is not a separate worksheet or submission. Use only the prompts that help your team develop a clear design.

## 1. Make the question measurable

Complete this sentence in your working notes:

> We will measure **[response]** as **[condition or variable]** changes so we can evaluate **[model behavior or engineering question]** for **[intended use]**.

If you cannot name the response or the model/decision it informs, narrow the question before choosing hardware.

## 2. State the expected behavior

Identify the governing relationship, model output, or physical reasoning. Define the primary quantities and units. State the response you expect and one assumption that could make the prediction inaccurate.

## 3. Plan a feasible comparison

In the proposal, identify the main quantity you will change or compare, the response you will measure, and the conditions needed to observe the expected behavior. Name only the controls or confounders that could materially affect the conclusion. Explain where repeating a measurement, changing the order, or documenting conditions matters.

## 4. Consider outside information

Find one credible source or alternative that informs a real design choice. A datasheet, paper, handbook, application note, measurement method, or relevant standard can qualify. Briefly record what it supports and what it does not.

## Proposal check

- [ ] The question is measurable and connected to a model or decision.
- [ ] The expected response is stated in terms of quantities students can measure.
- [ ] The proposed conditions are feasible and could distinguish a useful outcome.
- [ ] Important variables and confounders are considered.
- [ ] The outside source informs a specific choice.

Add this information to the existing proposal checkpoint. Do not submit this guide separately or repeat material in a later report.
