# Planning a Useful Model Comparison
## A short reference for the integrated Tier 3 proposal

A model comparison is useful when it is planned around a question. The proposal should say what physical response will be measured, what the model predicts for that response, and what evidence would count as support or challenge for the claim.

## Connect the parts

1. **Intended use:** What engineering decision or model use motivates the experiment?
2. **Prediction:** Which response feature should the model predict? State the expected trend, value, or range when available.
3. **Measurement:** Can the proposed instrument and conditions observe that feature?
4. **Uncertainty and limitations:** What could blur the comparison or change its interpretation?
5. **Criterion:** What numerical or otherwise defensible rule would you use to judge agreement for this intended use? Explain the basis; do not select a convenient tolerance without a reason.

The criterion should be stated before the proposed experiment is run. It can be a suitable difference, residual, trend, or requirement comparison. A single statistic does not prove a model valid for every use.

## Calibration and validation

Calibration establishes or checks an instrument’s relationship to a reference. Validation compares a model prediction with experimental evidence for a stated use. Calibration status can affect a validation conclusion, but calibration alone does not validate the model.

## Expected and unexpected data

State what data would look like if the prediction is reasonable. Name one plausible pattern that could indicate a measurement problem or an assumption/model limitation. Explain what the team would investigate before claiming that the model should change.

Add this short comparison strategy to the existing proposal. A full professional V&V plan, a section-by-section AMVF annotation, and an exhaustive risk register are not required.
